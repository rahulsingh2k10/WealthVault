# Database: `auth_platforms` Table

> Source of truth: `prisma/schema.prisma` (frontend). `backend/prisma/schema.prisma` is
> kept byte-identical for this model — the backend service has no logic of its own that
> touches `auth_platforms`, it just needs a matching schema against the same database.

## Overview

- **Prisma model name:** `AuthPlatform`
- **Table name:** `auth_platforms` (via `@@map("auth_platforms")`)
- **Database:** PostgreSQL, hosted on Railway (`DATABASE_URL` in `frontend/.env`)
- **Migration strategy:** no `prisma/migrations` history exists for this project — schema
  changes are applied directly with `prisma db push`.
- One row per OAuth sign-in provider (`GOOGLE`, `APPLE`, `X`, `LINKEDIN`) — a global
  reference table, not per-user data. Normalizes what was previously a free-form string
  column on `User` into an enum-backed, referentially-integral lookup.

---

## Column reference

| Column      | Type       | Nullable | Default  | Notes                                                |
|-------------|------------|----------|----------|------------------------------------------------------|
| `id`        | `String`   | No       | `uuid()` | Primary key                                          |
| `platform`  | `Platform` | No       | —        | Unique provider identifier (GOOGLE/APPLE/X/LINKEDIN) |
| `createdAt` | `DateTime` | No       | `now()`  | Row creation timestamp                               |
| `updatedAt` | `DateTime` | No       | auto     | Auto-updated on write                                |

### Column details

- **`id`** — UUID, generated by Prisma. Referenced by `users.platformId`. See **Relationships** below.
- **`platform`** — Unique. The provider name. Not a foreign key target from any other table's enum column — `users.platformId` references `id`, not this column.
- **`createdAt`** — Set once, at row creation.
- **`updatedAt`** — Updated automatically by Prisma on every write to the row (`@updatedAt`).

### Full current model (for reference)

```prisma
enum Platform {
  GOOGLE
  APPLE
  X
  LINKEDIN
}

model AuthPlatform {
  id        String   @id @default(uuid())
  platform  Platform @unique
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  users     User[]

  @@map("auth_platforms")
}
```

---

## Current data

Seeded once, directly against the live database — one row per `Platform` value
(`GOOGLE`, `APPLE`, `X`, `LINKEDIN`), each with a UUID `id`. Every OAuth callback route
looks up its own row by `platform` at sign-in time
(`prisma.authPlatform.findUniqueOrThrow({ where: { platform: "GOOGLE" } })`, etc.) rather
than hardcoding an `id`, since the actual id values are random and not predictable.

---

## Constraints & indexes

- **Primary key:** `id` (`uuid()`, generated by Prisma, not the database)
- **Unique constraint:** `platform` — enforces exactly one row per `Platform` value at the
  database level.
- No other indexes are defined.

---

## Relationships

`users.platformId` is a foreign key into `auth_platforms.id`:

```prisma
model User {
  ...
  platformId   String
  authPlatform AuthPlatform @relation(fields: [platformId], references: [id])
  ...
}
```

There is no `platform` column on `User` — the provider name is read via this relation
(`user.authPlatform.platform`), not stored on `User`. `GET /api/auth/me` performs this
join and returns the provider as `platform: "GOOGLE"` (etc.) in its JSON response.

The constraint is named `users_platformId_fkey` at the database level (verified via
`pg_constraint.confupdtype`/`confdeltype`). Practical implications:

- **Referential integrity is enforced by Postgres.** A `users.platformId` value must
  match an existing `auth_platforms.id` row — the database itself rejects a write
  otherwise.
- **You cannot delete an `auth_platforms` row while any user still references its `id`**
  — `ON DELETE RESTRICT` blocks it.
- **Updating an `auth_platforms.id` cascades automatically** — `ON UPDATE CASCADE` is
  set (Prisma's implicit default for this kind of relation), so changing a row's `id`
  updates every `users.platformId` that pointed at it in the same statement.
- **The reverse relation** `AuthPlatform.users User[]` lets application code fetch
  `prisma.authPlatform.findUnique({ where: { platform: 'GOOGLE' }, include: { users: true } })`
  to list every user who signed in with a given provider, though no code does this yet.
