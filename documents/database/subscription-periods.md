# Database: `subscription_periods` Table

> Source of truth: `prisma/schema.prisma` (frontend). `backend/prisma/schema.prisma` is
> kept byte-identical for this model — the backend service has no logic of its own that
> touches `subscription_periods`, it just needs a matching schema against the same
> database.

## Overview

- **Prisma model name:** `SubscriptionPeriod`
- **Table name:** `subscription_periods` (via `@@map("subscription_periods")`)
- **Database:** PostgreSQL, hosted on Railway (`DATABASE_URL` in `frontend/.env`)
- **Migration strategy:** no `prisma/migrations` history exists for this project — schema
  changes are applied directly with `prisma db push`.
- Zero or more rows per user — a one-to-many history of that user's subscription periods
  (start/end dates), rather than the single "current period" pair previously kept
  directly on `User`. No code currently creates, reads, or updates any row here.

### Column details

- **`id`** — Not referenced as a foreign key from any other table.
- **`userId`** — See **Relationships** below.
- **`startDate`** — When this subscription period began. Unused by any code — no route reads or writes it yet.
- **`endDate`** — When this subscription period ends/renews. Same status as above.
- **`createdAt`** — Set once, at row creation.
- **`updatedAt`** — Updated automatically by Prisma on every write to the row (`@updatedAt`).

### Full current model (for reference)

```prisma
model SubscriptionPeriod {
  id        Int       @id @default(autoincrement())
  userId    String
  user      User      @relation(fields: [userId], references: [id])
  startDate DateTime?
  endDate   DateTime?
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  @@map("subscription_periods")
}
```

## Constraints & indexes

- **Primary key:** `id` (auto-increment, generated by the database)
- **Foreign key:** `userId` → `users.id` — see **Relationships** below.
- No unique constraints — a user can have multiple period rows (that's the point of
  splitting this out of `User` as a one-to-many table).
- No other indexes are defined.

## Relationships

`subscription_periods.userId` is a foreign key into `users.id`:

```prisma
model SubscriptionPeriod {
  ...
  userId String
  user   User   @relation(fields: [userId], references: [id])
  ...
}
```

The reverse relation `User.subscriptionPeriods SubscriptionPeriod[]` lets application
code fetch every period a user has had via `prisma.user.findUnique({ where: { id }, include: { subscriptionPeriods: true } })`, though no code does this yet. No
`onDelete`/`onUpdate` modifier was specified, so Prisma leaves Postgres's default
(`NO ACTION`) in place — a `users` row can't currently be deleted while it still has
`subscription_periods` rows (moot today, since nothing writes rows here, but relevant
once this table starts being used).
