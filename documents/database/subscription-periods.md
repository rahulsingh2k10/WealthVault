# Database: `subscription_periods` Table

> Source of truth: `prisma/schema.prisma` (frontend). `backend/prisma/schema.prisma` is
> kept byte-identical for this model — the backend service has no logic of its own that
> touches `subscription_periods`, it just needs a matching schema against the same
> database.

## Overview

- **Prisma model name:** `SubscriptionPeriod`
- **Table name:** `subscription_periods` (via `@@map("subscription_periods")`)
- **Database:** PostgreSQL, hosted on Railway (`DATABASE_URL` in `frontend/.env`)
- **Migration strategy:** no `prisma/migrations` history exists for this project — schema
  changes are applied directly with `prisma db push`.
- One or more rows per user — an append-only history of which `SubscriptionPlan` a user
  has been on over time. A new row is inserted only when a user's plan differs from the
  one their most recent row recorded; rows are never updated. For a given user, the
  latest row (by `createdAt`) is their current plan; every earlier row records a plan
  they held in the past, and the gap between one row's `createdAt` and the next row's
  `createdAt` is how long they were on that plan.

## Column reference

| Column               | Type       | Nullable | Default  | Notes                                                 |
|----------------------|------------|----------|----------|-------------------------------------------------------|
| `id`                 | `String`   | No       | `uuid()` | Primary key                                           |
| `userId`             | `String`   | No       | —        | Foreign key to `users.id`                             |
| `subscriptionPlanId` | `String`   | No       | —        | Foreign key to `subscription_plans.id`                |
| `createdAt`          | `DateTime` | No       | `now()`  | Row creation timestamp — marks when this period began |

### Column details

- **`id`** — UUID, generated by Prisma. Not referenced as a foreign key from any other table.
- **`userId`** — See **Relationships** below.
- **`subscriptionPlanId`** — Which plan this period represents. See **Relationships** below.
- **`createdAt`** — Set once, at row creation. This is the only timestamp on the table — there is no `endDate` column; a period's end is implicit, marked by the `createdAt` of the user's next row (if any).

### Full current model (for reference)

```prisma
model SubscriptionPeriod {
  id                 String           @id @default(uuid())
  userId             String
  user               User             @relation(fields: [userId], references: [id])
  subscriptionPlanId String
  subscriptionPlan   SubscriptionPlan @relation(fields: [subscriptionPlanId], references: [id])
  createdAt          DateTime         @default(now())

  @@map("subscription_periods")
}
```

## Current data

Populated by `logSubscriptionPeriodIfChanged()` (`src/lib/services/SubscriptionPeriodService.ts`),
called from all four OAuth callback routes right after the `prisma.user.upsert(...)` call:

```typescript
export async function logSubscriptionPeriodIfChanged(userId: string, subscriptionPlanId: string): Promise<void> {
  const latest = await prisma.subscriptionPeriod.findFirst({
    where: { userId },
    orderBy: { createdAt: 'desc' },
  })

  if (!latest || latest.subscriptionPlanId !== subscriptionPlanId) {
    await prisma.subscriptionPeriod.create({
      data: { userId, subscriptionPlanId },
    })
  }
}
```

Every sign-in checks the user's most recent row against their current
`subscriptionPlanId`. A new row is only inserted when they differ (or the user has none
yet — the first login always logs one, recording the initial `FREE` plan every new
signup lands on). No other route or code path reads or writes this table.

## Constraints & indexes

- **Primary key:** `id` (`uuid()`, generated by Prisma, not the database)
- **Foreign key:** `userId` → `users.id` — see **Relationships** below.
- **Foreign key:** `subscriptionPlanId` → `subscription_plans.id` — see **Relationships** below.
- No unique constraints — a user can have multiple period rows (that's the point of this
  table: one row per distinct plan the user has held over time).
- No other indexes are defined.

---

## Relationships

**`subscription_periods.userId` → `users.id`** (foreign key, constraint
`subscription_periods_userId_fkey`, `ON DELETE RESTRICT`, `ON UPDATE CASCADE`): every
period row belongs to exactly one user. The reverse relation
`User.subscriptionPeriods SubscriptionPeriod[]` lets application code fetch a user's full
plan history via `prisma.user.findUnique({ where: { id }, include: { subscriptionPeriods: true } })`,
though no code does this yet.

**`subscription_periods.subscriptionPlanId` → `subscription_plans.id`** (foreign key,
constraint `subscription_periods_subscriptionPlanId_fkey`, `ON DELETE RESTRICT`,
`ON UPDATE CASCADE`): every period row references the plan it represents. The reverse
relation `SubscriptionPlan.subscriptionPeriods SubscriptionPeriod[]` lets application
code list every period ever logged for a given tier.

Both constraints block deleting a `users` or `subscription_plans` row while any
`subscription_periods` row still references it, and both cascade automatically on an
`id` update.
